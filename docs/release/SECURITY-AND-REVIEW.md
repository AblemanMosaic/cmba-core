## Trust inputs that remain outside the proof

Expected roots/profile commitments and recognized keys must come from an accepted reader
configuration. The host Python/Tk/crypto implementation, OS, keys, clock and protected
rollback floor are real trust dependencies. Supplied witnesses may collude; distinct keys
are not independent people. A signed false statement stays false. A consistent trace of an
incorrect transformation is not valid transformation evidence. Semantic hashes identify
exact descriptions; behavior requires actual checks, tests, accepted observation or proofs.

The core's finite parser/data limits do not sandbox arbitrary host code. Fixed installed
handlers are callable; input documents cannot load plugins. A caller-selected conformance
executable is host-authorized code, not sandboxed. GUI cancellation discards results and
does not forcibly stop arbitrary Python. Supported local effects assume a cooperating,
operator-owned filesystem and nonhostile host. No encryption, secret scrubbing, overwrite,
network fetch, public publishing or production key persistence is introduced.
