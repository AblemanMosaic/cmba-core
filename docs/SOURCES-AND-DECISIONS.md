# Source reconciliation and explicit decisions

## Available material

The direct conversation transcript and pasted assessment are preserved exactly. The Library
also supplied the original CMBA Framework Whitepaper, Mathematical Framework, and one exact-name
edition of Cryptographic Admissibility and Jurisdiction. Their raw bytes, Library identifiers and
SHA-256 hashes are in SOURCE-REGISTER.json. They are source material, not instructions to execute
anything, and their commercial/security assertions do not become runtime guarantees.

Five other titles mentioned in the assessment were not located by this retrieval. Their findings
remain secondary-attributed, not independently reproduced inspections. The program does not stop
because those sources are absent; their missingness is visible, and source-independent finite
contracts can still be implemented. The exact-name admissibility edition is pinned rather than
silently merged with differently named copies returned by the search.

## Decisions

**ADR-I-01 — Four build batches, I–L.** I gives executable common machinery, first profiles and a
native inspector; J realizes bounded family semantics and templates; K integrates the workbench
and explicitly gated local workflows; L qualifies a frozen candidate. External approval is not
scheduled into existence. The attached program specifies the completion conditions.

**ADR-I-02 — Preserve the application.** DKN Batch H stays frozen as its own installable library.
CMBA does not change its namespace roots, signatures, manifests, protocols, models or defaults.
An adapter references native identity and separately commits a wrapper. No forced upgrade.

**ADR-I-03 — No fixed dimensional ontology.** The later user clarification governs the new
architecture: dimension names are open-ended, objects are finite, profiles choose required roles.
This is not wire compatibility with the older universal object+causal rule. The difference is
explicit rather than described as though the original text already matched the new construction.

**ADR-I-04 — Research applications versus implementations.** The whitepaper's named table has
52 rows and eight section headings. It claims 51 and ten. Both are recorded. Catalogue presence,
record shape, predicate implementation, host integration and domain deployment are different
maturity properties. No row is marked operational merely because a binding can represent it.

**ADR-I-05 — Exact profile commitment.** A profile ID/version plus the complete profile-contract
hash selects an interpretation. A payload cannot supply an executable plugin path. Unknown
profiles remain inspectable but are not evaluated through guessed semantics.

**ADR-I-06 — Real, small semantic checks.** The initial CHC profile recomputes canonical JSON;
GenDev checks exact recorded spans and attribution; DKN calls its real native verifier. This
establishes reuse across different questions without pretending to have recreated the historical
compiler, consent, voting, medical, proof or governance engines.

**ADR-I-07 — Separate receipts and unsigned standing.** A receipt binds all evaluation inputs and
code identity. It is replayable but unsigned. Authority/evidence snapshots are recorded without
being interpreted by the I1 examples. No native signing/authority engine is slipped into the
core under a broad word such as verification.

**ADR-I-08 — Bindings before endorsements.** I1 binds the body without signatures. J will add a
separate endorsement/envelope profile; signatures may not participate in the body identity they
sign. Existing native DKN certificates remain untouched.

**ADR-I-09 — Native UI, optional.** A Tk workbench is selected to provide a real local GUI now,
without web servers or network exposure. It is a new reference UI, not a claim of integration
with an unprovided Mosaic UI Foundry. The core remains usable without Tk. Default workbench
operations are data-only reads; authoring/effect workflows are explicit K work.

**ADR-I-10 — No old security slogans.** Distinct dimensions do not imply independent defenses.
Hash chains do not prove compilation. Session extraction is attributed interpretation. Merkle
inclusion is not privacy. Popularity is not authority. All of those distinctions become future
predicate and test obligations instead of implicit inherited assurances.

**ADR-I-11 — Exact-type replacement checks.** Stable core conformance compares exact canonical
response bytes. Boolean/integer substitutions, JSON null, missing results and changed envelopes
must not receive PASS. Corpus expectations are frozen author-produced/reference-assisted data,
not an independent universal correctness oracle.

**ADR-I-12 — Narrow package license provenance.** Retain the inherited software license for the
new reference software and DKN baseline. Do not relabel user research papers or private session
records as public software assets, and do not infer patent/legal status from their assertions.
