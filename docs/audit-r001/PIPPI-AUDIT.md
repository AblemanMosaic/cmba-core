# P/PPI operation audit — evidence rather than naming

## Historical basis

The preserved transcript sources/DKN-core-CMBA-session-transcript-2026-11-07.md requested
exact-artifact custody and acceptance-case-bound work selection. It explicitly described
the early Windows session as SIDECAR_PARTIAL, not an enforced UCM/Pippi host. That transcript
excludes tool records, so it is not by itself a complete machine action log.

The frozen DKN baseline's docs/INTEGRATION-UCM-PIPPI-COURTHOUSE.md assigns acceptance case,
work selection, journal head, effect ceiling, jurisdiction and effect custody to the consumer.
acceptance/UCM-R030-REFERENCE.json pins historical atlas/pipeline/library hashes but explicitly
does not inherit the UCM authority model, admission, gateway or G1/G2/G3 custody. A hash of an
upstream program is not execution of that program.

## What was actually supplied and inspected

CMBA PROGRAM-LEDGER.json is an engineering batch ledger, not a proven native P/PPI program.
tools/verify_l.py and tools/verify_native_l.py are explicitly invoked local qualification
scripts. Model mappings provide bounded obligation/code/test traceability. The workbench's
pippi handoff contains references only and declares operational integration unestablished.

No owner-selected native P/PPI executable, native program schema/accepted translation,
registration/admission record, or host-mediated journal establishing all historical actions
was present in this supplied release. The exposed tools/skill catalogue in this audit did
not furnish the named ucm-pippi-mediated-agent or ugk-fga-iel-cgp skills or a native execution
interface. This is a scoped accessibility/evidence finding, not a claim that the user's
external installations do not exist. No live connector was used to submit or activate work.

## Verdict

**Artifact-mediated engineering discipline: demonstrated in the stated bounded checks, with
specific qualification/delivery defects now repaired. Native P/PPI operation: NOT_ESTABLISHED.**

This review uses its own prospective local PLAN and command/result captures. They start in
this audit; they are not native P/PPI receipts and do not backfill missing historical records.
There is no defensible blanket claim that every earlier step was acceptance-case selected,
natively admitted, or effect-fenced by P/PPI. Earlier handoffs/tests remain useful evidence
for the software properties they actually cover.

Runtime LocalEffects tests concern a user's application exports, not mediation of the
assistant's development process. Passing those tests does not prove the build session used
that mechanism for every edit, installation, command, or archive operation.

## Boundary preservation

Bindings, signatures and replay prove particular relationships under specified assumptions.
They neither grant jurisdiction nor select a legitimate authority. Documents opened during
this audit are evidence, not instructions to publish, transmit, install or invoke a host.
Native acceptance remains an explicit subsequent leg using real owner-selected interfaces.
