# Batch I status and Batch J entry boundary

This is a separately selected CMBA successor, not a silently modified DKN release. The complete
frozen DKN Batch H archive, wheel and external records are preserved under baseline/dkn. The
source register binds five retrieved source documents independently of engineering proposals.

## Delivered I1 scope

The standalone core has no third-party runtime dependency. It supplies a bounded canonical
codec, typed dimensions/references and binding roots, exact profile-contract lookup, finite
profile evaluation, context-bound unsigned receipts, recomputing replay, comparison and a closed
read-only JSON interface. Four profiles exist: generic bindings, frozen DKN artifact descriptions,
one actually checked CHC canonical-JSON transformation, and attributed GenDev source spans.
The DKN bridge can additionally verify supplied archive bytes and a detached native certificate.
The ordinary DKN-profile receipt does not claim a payload check when only a manifest is supplied.

The native Tk workbench opens finite bundles, shows dimension commitments and context, browses
71 catalogue records, computes profile results and replays receipts. Its document-context option
is explicitly a demonstration, never trusted pin acquisition. The library accepts reader-owned
context; the I workbench does not yet provide a complete policy-management or authoring UI.

The catalogue preserves 52 rows from the recovered whitepaper table and 19 cross-cutting family
mappings. It separately records absent original papers and terminology conflicts. Domain entries
are descriptive research records, not deployed domain applications. No election, clinical,
weapon-control or legal decision system has been implemented by registering their names.

## Findings and revisions retained

1. The first new-suite run found a nonregular-file refusal-code mismatch. CLI admission now
   checks the descriptor before treating it as a byte stream, with a regression test.
2. The GUI smoke checked explicit context selection and positive, negative and replay paths.
   Its first screenshot exposed an offscreen status/footer; layout and capture were corrected.
3. Build-generated egg-info is excluded from the source replay fingerprint, with a regression
   showing that changes to actual source still change that fingerprint.
4. The initial optional-install probe mistakenly assumed a native certificate `status` field.
   It was corrected to test `signature=PASS` and `authorization=NOT_CHECKED`, without changing DKN.
5. An initial system-site-packages environment inherited different packages from the active
   host environment; pip check failed. It is retained as failed dependency evidence, not an
   accepted installed leg. The final separate optional environment uses inventoried exact copies
   of genuine active-host distributions and passes pip check. No fresh dependency download is claimed.

Intermediate failures and corrected local results remain in evidence/batch-i. Final transport
hashes and extraction evidence are external to the source ZIP to avoid circular commitments.

## Batch J construction, without widening the accepted core

Start from this exact release. Implement the bounded family evaluators specified in
PROGRAM-I-L.md: full DKN adapters, transformation graphs/checks, session derivation, overlapping
jurisdictions, renewable scoped consent, selected policy predicates, disclosure construction,
measurements, coordination, reconciliation and execution-record comparison. Introduce a separately
versioned native endorsement/signature profile before interpreting signed approvals. Reuse pinned
DKN cryptography explicitly or another qualified backend; do not invent cryptographic primitives.

Each evaluator requires its exact dimensions, schemas, predicates, authority assumptions,
resource limits, result contract, negative cases and model-to-realization binding. No plugin loader
may execute code named by an opened document. Keep every historical domain template visibly
incomplete where its domain validation or source implementation is unavailable. Scope external
UCM/CCP/P-PPI/Courthouse integrations as contracts until those implementations are actually bound.
